# 缓动规范

`custom/` 下的动效组件共用这一套缓动语汇。目的只有一个：**让它们看起来像出自同一只手**。

上游那 139 个组件的缓动是各写各的（`SplitText` 用 `power3.out`、`ScrollStack` 靠 lenis、
别的组件各有各的 `transition`），凑在一个页面里手感是散的。自有组件不能再这样。

---

## 为什么要「夸张」

默认的 `ease-out` 是单调收敛的——冲向终点，减速，停下。数学上无可挑剔，看着像 PPT。

真实物体停不下来。它会**冲过去一点，再荡回来**。这一点点超调就是「有劲」和「没劲」的分界，
也是本规范里所有曲线的共同点。

```
ease-out          ▁▂▄▆▇███        到点即停
overshoot         ▁▂▄▆█▇█▇█       冲过头 → 荡回 → 落定
```

---

## 曲线表

CSS 场景（`transition` / `animation`）直接用这几条 `cubic-bezier`：

| 名字 | 值 | 什么时候用 |
|---|---|---|
| `overshoot` | `cubic-bezier(.34, 1.56, .64, 1)` | **默认选它**。冲过头再回落，适合入场、展开、落位 |
| `overshootHard` | `cubic-bezier(.22, 1.85, .36, 1)` | 更狠的过冲，会明显荡一下。用在需要抢注意力的地方 |
| `anticipate` | `cubic-bezier(.68, -.55, .27, 1.55)` | 先反向蓄力再冲出。适合「发力」感强的切换 |
| `glide` | `cubic-bezier(.16, 1, .3, 1)` | 极快启动、长尾收束，**无过冲**。适合虚化、透明度这类不该弹的属性 |

**别给 `opacity` 用超调曲线**——透明度冲过 1 是看不见的，只会让淡入显得迟钝。
位移、缩放、旋转用 `overshoot`，透明度和模糊用 `glide` 或 `linear`。

## 函数版

滚动驱动的组件按进度逐帧求值，用不了 CSS 曲线，用这两个纯函数（与上表一一对应）：

```ts
/** 冲过头再回落。对应 cubic-bezier(.34,1.56,.64,1)。s 越大冲得越过 */
const easeOutBack = (t: number, s = 1.70158) => 1 + (s + 1) * (t - 1) ** 3 + s * (t - 1) ** 2;

/** 极快启动、长尾收束，无过冲。对应 cubic-bezier(.16,1,.3,1) */
const easeOutExpo = (t: number) => (t >= 1 ? 1 : 1 - 2 ** (-10 * t));
```

`easeOutBack(t)` 在 t 接近 1 时**返回值会大于 1**——这是特性不是 bug，超调就来自这里。
所以拿它算 `opacity` 或任何有上界的量时记得钳住。

## 弹簧

「追随」类的效果（`RingCarousel` 追滚动、`FluidWarp` 回弹）不该用固定时长的曲线——
目标一直在动，曲线每次都得重来。用弹簧，它天然处理「目标变了」：

```ts
/** 半隐式欧拉。dt 要钳住，切标签页回来会给出巨大的 dt 把弹簧炸飞 */
function springStep(value, velocity, target, stiffness, damping, dt) {
  const nextV = (velocity + (target - value) * stiffness * dt) * Math.exp(-damping * dt);
  return [value + nextV * dt, nextV];
}
```

| 参数 | 调大会怎样 | 常用区间 |
|---|---|---|
| `stiffness` | 跟得更紧、更快 | 80 ~ 260 |
| `damping` | 更快收敛、过冲更少 | 8 ~ 16（**低于 10 才明显荡** ） |

想要「糯」就降 `damping`，想要「脆」就升 `stiffness` 同时升 `damping`。

## 错峰

「错落有致」不是让元素随机延迟，是让它们**按一个看得懂的次序**依次到位。

```ts
/** 第 i 个（共 n 个）的次序 0~1，0 最先动 */
function orderOf(i, n, from) {
  const last = n - 1;
  switch (from) {
    case 'end':    return (last - i) / last;                      // 倒序
    case 'center': return Math.abs(i - last / 2) / (last / 2);    // 从中间往两边
    case 'edges':  return 1 - Math.abs(i - last / 2) / (last / 2);// 从两边往中间
    case 'wave':   return (1 - Math.cos((i / last) * Math.PI * 2)) / 2;
    case 'random': { const h = Math.sin(i * 12.9898 + 78.233) * 43758.5453; return h - Math.floor(h); }
    default:       return i / last;                                // 顺序
  }
}
```

`random` 用的是**确定性**伪随机（不是 `Math.random()`）。刷新页面顺序不变——
每次都不一样的动画会让人觉得是坏了。

**间隔怎么定**：相邻元素差 30~60ms 最舒服。低于 20ms 看起来像一起动，
高于 100ms 会让人等得不耐烦。元素多的时候不要线性叠加总时长，
用 `orderOf(i,n) * stagger * n` 把总跨度控制住。

### 层级错峰

同一块内容里的元素也要分先后，别一起弹出来。约定三级：

| 层 | 什么东西 | 相对延迟 |
|---|---|---|
| 0 | 主标题 | 0 |
| 1 | 副标题 / 正文 | `stagger` |
| 2 | 装饰线 / 图标 / 次要元素 | `stagger × 2` |

实现方式是在 DOM 上标 `data-part="0|1|2"`，驱动时把同一个进度 `k` 依次往后推再归一化：

```ts
const kj = clamp01((k - j * stagger) / (1 - j * stagger));
```

`ScrollScenes` 和 `SnapSections` 都是这么做的，照抄即可。

---

## 为什么这些代码在每个组件里各有一份

因为这个库的分发形态是**取用 = 拷一个文件**。

`scripts/lib/resolve.mjs` 的 `importedAssets()` 明确排除 `.tsx/.ts/.jsx/.js/.css`——
相对 import 的本地模块不会被取用链路带走，跨文件互引的组件拷出去直接编译不过。

所以曲线表和这几个纯函数在 6 个组件里各内联一份，都带同一条注释：

```
/* ── 缓动语汇 · custom/ 下 6 个动效组件共用，改一处要六处同步 ── */
```

**改任何一条曲线，六处都要改。** 这是为分发形态付的代价，别想着抽公共模块。

## 用了这套规范的组件

| 组件 | 缓动来源 | 错峰形式 |
|---|---|---|
| `FluidWarp` | 弹簧（回弹） | — |
| `ScrollScenes` | `easeOutBack` + `easeOutExpo` | 场景内三级 |
| `RingCarousel` | 弹簧（追随滚动） | 每张卡刚度微差 |
| `StaggerReveal` | CSS 曲线表 | 六种次序 × 五种姿态 |
| `SnapSections` | `easeOutBack` + 弹簧吸附 | 屏内三级 |
| `StackTransition` | `easeOutBack` | 逐层压叠 |
